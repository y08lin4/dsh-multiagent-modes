# 多 Agent 协作模式

> 主代理是「权衡器」，不是「查表路由器」。本文档给的是**维度 + 代价 + 锚点**，
> 不是死表格。每次拆任务时由主代理按任务语义现推，18 格仅作附录参考。

---

## 一、核心立意：思维链保真 + 效率

**最强卖点——思维链不丢失**：主代理单干时，全部思考与中间产物堆在主上下文，
一旦触发压缩，早期推理被摘要化、后续决策失去依据——思维链断裂。
子代理模式把**完整推理过程留在子会话里**，只回传浓缩结论；主代理上下文
只装决策点与结论，几乎不再触发压缩，其拆解、验收、决策的思维链全程保真。

**第二卖点——效率**：子代理并行执行，主代理只决策、不干重活；
细拆多轮、边收边吸收——吞吐来自「分工正确」，不是无脑堆并发。

**顺带收益——省 token**：回传压缩 + 细拆多轮自然压低 token，但它是
「保真 + 分工」的副产品，不是目的；不为了省 token 而牺牲思维链完整。

**缓存原则**（从简，不刻意）：历史会话能复用的就复用（`fork` 继承），没必要复用的
就开独立会话（`subagent`）；**不刻意追求缓存率**。

**三条执行杠杆（保真 + 效率 + 顺带省 token）：**

1. **回传压缩**（最重）：子代理是过滤嘴，回「结论」不回「过程」。
2. **细拆多轮**（最重）：任务拆小、每轮增量小，主代理边收边吸收——不触发压缩、
   不丢细节。**两个速率档都适用**，均衡档尤其以此为主。
3. **汇报格式分级**（中）：按主代理「怎么消费回传」选格式，见第五节。

> 已否决：强制英文交流——只省边际 token，中文语境任务会引入翻译损耗与语义漂移，
> 得不偿失。

## 二、两个速率档

| 名称 | 并行策略 | 适用 |
|---|---|---|
| **协作模式-均衡** | 单轮并发 **10**（默认），**细拆多轮**、每轮增量小、边做边吸收 | 默认档，日常任务 |
| **协作模式-高效** | 单轮并发 **20**，**积极多轮** fan-out（不强制），追求吞吐与效率 | 有余额、赶时间、大量独立子任务 |

> 速率档只决定「同时跑几个、跑多快」，与「每个子任务用什么模型/思考」完全正交。
>
> **两档都细拆多轮**：细拆 + 多轮本身就是省 token 手段（见第一节杠杆 2），不是高效的专利。
> 真正的分水岭是**并发与每轮密度**：均衡细水长流，高效油门踩深。
>
> **「积极多轮」的度**：高效档要更主动地发起子代理、更愿意连续补几轮，但**不要过度供给**——
> 并发上限是天花板不是目标，不为了「凑满 20」而硬拆任务；没那么多独立活时，少发比多发更省、更稳。

## 三、三个正交维度 + 代价（核心，主模型推导用）

每次委派一个子任务，就是在这三个旋钮上各取一档。**不要背格子，要背这三行的代价直觉：**

```
① 模型：   flash（快、省）            pro（准、贵）
② 思考：   off（零推理）  minimal/low（快速）  medium/high（正常）  xhigh（疑难）  max（烧脑）
③ 委派：   subagent（独立会话，不吃上下文）
           fork（继承本对话）
           workflow（规模化、结构化 fan-out）
```

**取舍直觉（每次现推，不是规则匹配）：**

- **模型**：机械 / 简单 / 大量 → flash；复杂 / 关键路径 / 要准 → pro。落地：`subagent` / `subagent_fork` 传 `model` 参数（不传 = 继承主代理模型）。
- **思考**：批量/机械 → off；简单执行 → minimal / low；正常推理 → medium / high；疑难排查 → xhigh；关键决策 / 高风险变更 → max。落地：同上工具传 `effort` 参数（不传 = 模型默认档；拿不准从 medium 起，不够准升档、太贵降档）。
- **委派**：
  - 要复用历史上下文 → fork；
  - 不需要上下文 → subagent；
  - 成规模、要结构化收敛、大量同构分片 → workflow。

## 四、六个锚点（只做校准，不做穷举）

锚点的作用：**省 token（高频场景不用现推）+ 防漂移（校准「机械/烧脑」的基准）**。

| # | 委派 | 模型 | 思考 | 典型场景 |
|---|---|---|---|---|
| ① | subagent | flash | off | 独立机械小活：查 API、跑脚本、格式化、提取字段 |
| ⑤ | subagent | pro | high | 独立硬活：单模块重构、算法实现、独立设计 |
| ⑦ | fork | flash | off | 承接式核对：基于已有结论快速核对、打补丁 |
| ⑪ | fork | pro | high | 承接式延续：延续设计、后续分析、补充实现 |
| ⑬ | workflow | flash | off | 批量机械分片：批量审计、迁移、提取 |
| ⑰ | workflow | pro | high | 多角度研究：并行深度分析、多方案对比 |

> 遇到不在锚点里的任务，用第三节的三个维度现推，不要硬套。

## 五、汇报格式分级（回传规范）

原则：**格式跟着「消费方式」走，不跟「任务类型」走。**

| 主代理拿回传做什么 | 回传格式 |
|---|---|
| 汇总 / 比对 / 计数（多份结果机械整合） | **JSON**（字段 schema 在派发 prompt 里给，workflow 优先用 `agent(prompt, { schema })` 硬校验） |
| 阅读理解 / 再设计 / 直接引用 | **结构化 markdown 或代码块**（结论先行，别硬塞 JSON） |
| 单一结论类交付 | 精炼 markdown：**结论（1~3 行）→ 关键依据（要点）→ 风险/不确定项** |

硬规则：

- 每个子任务 prompt 里**必须写清回传格式**（或引用本表），子代理才知道「什么是需要的」。
- 禁止回传：过程流水账、完整工具日志、与结论无关的中间产物。
- JSON 场景给「字段示例」而不是让子代理自由发挥，避免凑格式写废话。

## 六、速率档的实现参数（当前部署真实旋钮）

| 旋钮 | 全局值 | 均衡（软限制） | 高效（软限制） | 位置 |
|---|---|---|---|---|
| `maxParallelToolCalls` | **20**（一次设好，最大值） | ≤ 10 | ≤ 20 | settings `agent-loop`（Web GUI 有设置项） |
| 思考档 `off` 映射 | `off:"none"` | — | — | settings `agent-loop`（wire 值映射；raw `off` 直发中转会 400，是 `effort=off` 的硬前提，插件内不兜底） |
| workflow `maxConcurrentAgents` | 默认自动 `min(16, CPU−2)` | 默认自动 | 20~24（如需） | preset 的 `workflow-worker-thread` 行 |
| 后台 job `maxConcurrentJobsPerOwner` | 10（默认） | 10 | 调大 | host `jobs` config |

**硬并发与软限制**：硬上限（settings）全局设成**需要的最大值 20**，两档差异全部由
persona 软限制实现——均衡档自我约束 ≤ 10，高效档可用到 ≤ 20。**硬上限只兜底、
不驱动行为**；实际发几个永远由「当时有多少独立子任务」决定。

**速率档语义**：
- **均衡** = 软限制单轮并发 10，**细拆多轮、每轮增量小、边做边吸收**。
- **高效** = 软限制单轮并发 20，**积极多轮但不强制**：连续几轮把总吞吐推到 50+ 是目标方向，
  但每轮发几个、发几轮，由当时真正有多少独立子任务决定——**不硬凑、不过剩**。

**「拉满」的真实边界**：不在程序校验（这些旋钮 schema 均无上限），而在 **CPU/内存** 与 **DeepSeek API 限流（RPM/TPM）**。高效档的正确形态是「并发 20 × 积极多轮」，不是单轮无脑拉满（后者触发 429 反而更慢）。

## 七、技术现状（务必知道哪部分已可用）

| 能力 | 现状 |
|---|---|
| 三个维度的**判断与拆解** | ✅ 现在就能做（本文档作为参考） |
| `workflow` 指定 **model** | ✅ 已可用（`agent(prompt, { model })`） |
| `subagent` / `subagent_fork` 指定 **model** | ✅ 已接通（本预设本地插件 `plugins/subagent-routed.v2.js`，`model` 参数） |
| `subagent` / `subagent_fork` 指定 **思考档 effort** | ✅ 已接通（同插件 `effort` 参数，七档 off/minimal/low/medium/high/xhigh/max，经 ContinuableSetupContribution 的 agent/request proxy 注入） |
| one-shot / workflow 子代理指定思考档 | ❌ 不经过 proxy，走模型默认档 |

> 思考档 proxy 依赖 `agentOptions` 运行时透传这一非正式契约，官方未来加校验可能失效；
> 上游最小改动方案（3 包 5 处）见仓库 `docs/upstream-proposal.md`。

## 附录：18 格全集（参考，勿背）

### A 组 · `subagent`（独立会话）

| | flash | pro |
|---|---|---|
| **off** | ① 机械小活（高频） | ④ 规范硬活：照死规范机械重构（中频） |
| **high** | ② 轻推理小活（中频） | ⑤ 独立硬活（高频） |
| **max** | ③ 烧脑小活（罕见，性价比低） | ⑥ 独立烧脑活（中频） |

### B 组 · `subagent_fork`（继承本对话）

| | flash | pro |
|---|---|---|
| **off** | ⑦ 承接式核对（高频） | ⑩ 承接式照做：计划已定按步执行（中频） |
| **high** | ⑧ 承接式整理（中频） | ⑪ 承接式延续（高频） |
| **max** | ⑨ 烧脑整理（罕见） | ⑫ 承接式深度决策（中频） |

### C 组 · `workflow`（结构化 fan-out）

| | flash | pro |
|---|---|---|
| **off** | ⑬ 批量机械分片（高频） | ⑯ 批量规范重构（中频） |
| **high** | ⑭ 批量轻推理分片（中频） | ⑰ 多角度研究（高频） |
| **max** | ⑮ 批量烧脑分片（罕见） | ⑱ 对抗性验证（中频） |

> A/B 组经 `subagent` / `subagent_fork` 的 `model` + `effort` 参数执行（每单指定）；
> C 组经 `workflow` 的 `model` 参数执行，思考档不经过 proxy（走模型默认档）。
>
> flash + max 一行（③⑨⑮）基本是「理论格」，日常几乎不碰；18 格里的实用骨架
> 集中在 ①⑤⑦⑪⑬⑰ 六个锚点上下，其余中频按需。
>
> **七档细调对照**：18 格里的 off ≈ off；high ≈ medium/high；max ≈ xhigh/max。
> 新增的 minimal/low 是「简单执行」中间档（格内不列），按第三节五档规则现推。
