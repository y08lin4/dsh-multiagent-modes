1. **effort proxy 链静默失效**：子代理不报错但档位没透传。第 3/4 步专门验证——
   `off` 的子代理若仍长篇思考、`max` 的子代理若秒回敷衍，说明
   agentOptions → reasoningEffort → 子代理请求 这条链断了，需要查
   `subagent-routed.v2.js` 的 ContinuableSetup 代理。
2. **model 参数路由**：`model=deepseek-v4-pro` 的子代理是否真跑在 pro 上
   （耗时/质量应有感知差异）。
3. **schema 修复后的真实派发**：第 1/3 步验证 v4 的 `required:["description","prompt"]`
   在真实模型调用中通过中转校验。
